# 演示操作指南 — Demo Guide

本文档提供 nano_finance 项目的 5 个演示场景的分步操作说明。每个场景覆盖系统的一项核心能力，可按任意顺序演示。

---

## 环境准备

在开始演示前，确保以下条件已满足：

1. **服务已启动**：Model（18001）、Backend（18002）、Frontend（18003）三个服务均在 tmux 中运行。
   ```bash
   bash scripts/deploy/start_all.sh
   ```

2. **SSH 隧道已建立**（如需远程访问）：
   ```bash
   ssh -N -L 18003:127.0.0.1:18003 -L 18002:127.0.0.1:18002 <user>@<server>
   ```

3. **浏览器打开** `http://127.0.0.1:18003`

4. **上传文档已就绪**：确保 `data/` 目录下有财务报告 PDF 文件（例如年报）。

---

## 场景一：财务报告问答（Financial Report Q&A）

**目标**：演示 RAG 系统的完整链路——上传文档、提问、查看来源引用。

### 操作步骤

1. **上传文档**：在 Web UI 中点击"上传"按钮，选择一份中文财务报告 PDF（例如某公司年度报告），等待上传完成并索引建立。

2. **提问**：在对话框中输入：
   > 该公司2024年的营业收入是多少？

3. **查看回答**：系统返回答案，包含：
   - 自然语言回答
   - 引用来源标注（文档名 + 页码）
   - 可点击的来源链接

4. **追问**：继续输入：
   > 与2023年相比，营业收入变化了多少？

   系统应能在同一文档上下文中回答。

### 验证点

| # | 检查项 | 预期结果 |
|---|--------|----------|
| 1 | 答案包含具体数值 | 数值来自上传的文档 |
| 2 | 答案附带来源引用 | 显示文档名和页码 |
| 3 | 来源链接可点击 | 跳转到文档对应位置 |
| 4 | 追问保持上下文 | 在同一会话中正确回答 |

## 场景二：确定性财务计算（Deterministic Financial Calculation）

**目标**：演示确定性 Calculator 的 9 种金融操作，展示操作数证据绑定。

### 操作步骤

1. **提问增长率**：
   > 该公司2023年到2024年的营业收入增长率是多少？

2. **观察回答**：系统不通过 LLM 做自由计算，而是：
   - 从文档中提取 2023 和 2024 年的营业收入
   - 调用确定性 Calculator 的 `growth_rate` 操作
   - 返回计算结果 + 操作数来源（文档、页码、chunk）

3. **提问毛利率**：
   > 该公司2024年的毛利率是多少？

4. **提问负债率**：
   > 该公司2024年的资产负债率是多少？

### 验证点

| # | 检查项 | 预期结果 |
|---|--------|----------|
| 1 | 计算使用 Decimal 精度 | 无浮点误差 |
| 2 | 操作数附带证据引用 | 每个数字标注来源 |
| 3 | 计算过程可追溯 | 显示使用的操作类型 |
| 4 | 支持的操作有 9 种 | 可提问不同操作类型 |

## 场景三：单位/期间歧义阻断（Unit/Period Ambiguity）

**目标**：演示系统在面对歧义问题时的安全阻断机制，不会猜测。

### 操作步骤

1. **制造歧义**：输入一个单位不明确的问题：
   > 该公司收入增长了多少？

   （"多少"未指定是绝对值还是百分比）

2. **观察阻断**：系统应返回类似：
   > 无法确定您的问题。请明确：是绝对差值还是增长率？

3. **再次制造歧义**：输入一个期间不明确的问题：
   > 与去年相比，利润变化了多少？

   （"去年"在文档有多年数据时可能歧义）

4. **观察阻断**：系统应要求明确期间。

5. **修复问题后重新提问**：
   > 该公司2023年到2024年的营业收入增长率是多少？

   此时应正常返回计算结果。

### 验证点

| # | 检查项 | 预期结果 |
|---|--------|----------|
| 1 | 歧义问题不被猜测 | 返回阻断消息 |
| 2 | 单位歧义被拦截 | 提示明确单位 |
| 3 | 期间歧义被拦截 | 提示明确期间 |
| 4 | 明确问题后正常计算 | 返回正确结果 |
| 5 | 不 fallback 到 LLM 计算 | 不会看到模型自由计算的结果 |

## 场景四：不可回答问题安全拒绝（Unanswerable Questions）

**目标**：演示系统在面对超出文档范围的问题时的安全拒绝机制。

### 操作步骤

1. **提问超出文档范围的问题**：
   > 苹果公司2024年的营业收入是多少？

   （假设上传的文档不包含苹果公司信息）

2. **观察拒绝**：系统应返回类似：
   > 当前文档中未找到与"苹果公司"相关的信息。请上传相关文档后重试。

3. **提问无证据支撑的问题**：
   > 该公司明年预计增长率是多少？

   （文档不包含未来预测数据）

4. **观察拒绝**：系统应安全拒绝，而不是编造答案。

5. **对比演示**：再上传一份包含相关信息的文档，同样的问题可以得到回答。

### 验证点

| # | 检查项 | 预期结果 |
|---|--------|----------|
| 1 | Answerability 校验触发 | 检测到文档不包含相关信息 |
| 2 | 系统安全拒绝 | 不编造答案 |
| 3 | 拒绝消息清晰友好 | 说明原因并给出建议 |
| 4 | 补充文档后可回答 | 上传相关文档后正常回答 |

## 场景五：在线三服务状态检查（Online Three-Service Status）

**目标**：演示部署架构的三个服务、健康检查和 SSH 隧道访问。

### 操作步骤

1. **查看服务状态**：
   ```bash
   bash scripts/deploy/status.sh
   ```
   输出应显示三个 tmux 会话：
   - `nano-finance-model` — 运行中
   - `nano-finance-backend` — 运行中
   - `nano-finance-frontend` — 运行中

2. **运行健康检查**：
   ```bash
   python scripts/deploy/healthcheck.py
   ```
   所有检查项应为 pass。

3. **逐服务验证**：
   ```bash
   curl http://127.0.0.1:18001/health    # Model service
   curl http://127.0.0.1:18002/healthz   # Backend service
   curl -I http://127.0.0.1:18003        # Frontend (HTTP 200)
   ```

4. **验证服务链路**：在 Web UI 中发送一个问答请求，确认请求经过 Frontend → Backend → Model 的完整链路。

5. **验证 SSH 隧道**：在本地浏览器中通过 `http://127.0.0.1:18003` 访问，确认可以通过隧道正常使用。

6. **验证重启恢复**：
   ```bash
   bash scripts/deploy/restart_all.sh
   python scripts/deploy/healthcheck.py  # 再次检查应全部通过
   ```

### 验证点

| # | 检查项 | 预期结果 |
|---|--------|----------|
| 1 | 三个服务均在运行 | `status.sh` 显示三个会话 |
| 2 | 健康检查全部通过 | 42/42 Phase 7 验收标准满足 |
| 3 | 冒烟测试 12/12 通过 | 包含 health、Q&A、计算、SSE、重启 |
| 4 | 服务链路完整 | 请求正确经过三跳 |
| 5 | SSH 隧道可访问 | 本地浏览器能打开 |
| 6 | 重启后恢复 | 重启后所有服务在线 |

## 注意事项

1. **不支持原生 Function Calling**：Calculator 调用由系统编排，不是模型原生能力。演示中不要声称"模型自己调用了计算器"。
2. **不声称消除幻觉**：即使通过 Validation，模型仍可能产生幻觉。系统是 fail-closed 设计，但不能保证完全消除。
3. **不声称生产级精度**：0/54 synthetic-held-out 结果不代表质量，不作为质量指标引用。
4. **不声称 tokenizer 提速**：tokenizer 压缩率不等于推理速度提升。
